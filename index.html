02 / implementation

What Dylan engineered.

The objective was not to make a mascot talk once. It was to create a bounded, responsive system whose stages could be observed, tested, and recovered independently.

01

Desktop build recovery

Recovered the application workspace, verified relevant packages, rebuilt the desktop experience, and accepted the installed behavior—not just compiler output.

02

Onboarding hardening

Corrected provider-detection and persisted-state behavior so a valid local setup did not fall back into an unnecessary setup loop.

03

Streamed local conversation

Connected a local model lane with streamed output and bounded spoken replies, reducing the wait before useful content appeared.

04

Persistent speech recognition

Kept local recognition available as a service stage instead of paying model startup cost on every voice turn.

05

Local speech + lip-sync

Connected local synthesis to playback and avatar speech behavior, then verified visible mouth, face, and body-state changes during audio.

06

Operational boundaries

Separated health, readiness, timeouts, recovery, and graceful degradation so one unavailable component did not silently redefine the whole system.

05 / safety boundary

Show the engineering. Protect the system.

The public artifact is intentionally useful without becoming a map of the private deployment or a copy of someone else's project.

What this case study establishes

  • The tested core conversation loop ran locally.
  • Recognition, conversation, synthesis, and playback were separate stages.
  • Real audio and visible avatar behavior were exercised.
  • Readiness and degraded states were treated as engineering concerns.
  • Upstream ownership and Dylan's contribution are separated clearly.

What stays private

  • Credentials, provider secrets, and authentication material
  • Prompts, memories, transcripts, logs, and personal data
  • Machine paths, ports, service definitions, and backups
  • Internal routing, operational control surfaces, and runtime state
  • Upstream AIRI source, models, characters, artwork, and assets
06 / lessons

What the build proved.

The value is not the avatar alone. It is the engineering discipline required to make a multi-stage local interaction fast, understandable, and recoverable.

Local does not mean simple.

Private systems still need timeouts, readiness, bounded retries, and truthful degraded states.

Voice is a pipeline.

Recognition, generation, synthesis, playback, and animation each need their own contract.

The interface is telemetry.

Listening, thinking, speaking, unavailable, and recovering states should communicate reality.

Streaming changes perception.

Beginning useful output early matters more to a conversation than optimizing one isolated total.

A green build is not acceptance.

Real audio, visible avatar transitions, and recovery behavior must actually be exercised.

Public artifacts need threat models.

You can show architecture and judgment without exposing private implementation details.
